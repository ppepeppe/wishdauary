# WishDauary · 위시다유어리

아이의 일기와 가족의 응원, 클로버로 부탁하는 선물을 함께하는 가족용 앱입니다.

## 구성

- `frontend/`: React · TypeScript · Vite 웹 화면과 Capacitor Android/iPhone 프로젝트
- `backend/`: Java 21 · Spring Boot · PostgreSQL API
- `frontend/MOBILE.md`: 모바일 앱 빌드와 로컬 기기 연결 안내
- `compose.yaml`, `deploy/`: EC2 한 대에서 웹·API·PostgreSQL 실행, HTTPS·백업 안내

EC2 배포는 [서버 배포 안내](deploy/README.md)를 따릅니다. `sh deploy/init-env.sh`로 비밀값을 생성하고 접속 주소를 설정한 뒤 Docker Compose로 실행합니다. 기존 로컬 DB를 유지하려면 안내의 백업·복원 단계도 진행합니다.

## 주요 기능

- 이메일 인증 없이 아이디·비밀번호로 가입·로그인
- 아이의 일기 작성, 공개 범위와 공유 그룹 관리
- 어른의 아이 검색·연결 요청과 아이의 승인·거절
- 어른용 홈, 아이 일기 열람·댓글·하트
- 아이의 희망 상품 등록, 가족의 선물 등록·클로버 설정과 수정
- 선물 요청 승인·거절과 클로버 사용·환불
- 프로필과 가족 연결 관리
- 관리자·일반 사용자 권한 저장과 관리자 공통 상점 상품 등록

## 계정 로그인

아이·가족 모두 이메일 주소 대신 공백 없는 아이디와 비밀번호로 가입합니다. 한글 아이디도 사용할 수 있으며 아이디는 최대 255자입니다. 아이디는 아이·가족 전체에서 중복될 수 없습니다. 기존 계정은 이전 이메일 주소를 아이디 칸에 입력하면 같은 비밀번호로 로그인할 수 있습니다.

인증 API의 기본 필드는 `loginId`이며 구버전 앱의 `email` 요청 필드도 호환합니다. 프로필은 `loginId`와 구버전 호환용 `email`을 함께 반환합니다. 기존 DB의 `users.email` 컬럼을 로그인 아이디에 매핑해 사용하므로 데이터 변환이나 계정 재생성은 필요 없습니다.

가족 계정은 마이페이지의 **아이와의 관계**를 수정할 수 있습니다. 저장한 호칭은 연결된 아이의 가족 목록·선물 요청 대상 등에 반영됩니다. 관계를 보내지 않는 구버전 프로필 수정 요청은 기존 호칭을 유지하며, 이전 선물 요청에 저장된 당시 호칭은 변경하지 않습니다.

가입 시 닉네임과 아이와의 관계의 앞뒤 공백을 제거하고, 각각 1~20자와 1~100자로 제한합니다. 가족의 아이 검색은 한 글자 닉네임을 정확히 일치하는 경우에만 찾고, 두 글자 이상은 부분 검색합니다. 동명이인은 아이 마이페이지의 사용자 번호로 구분할 수 있습니다.

## 클로버 적립 정책

아이별로 기록 날짜당 일기 1편만 저장할 수 있으며, 기본 클로버 1개를 적립합니다. 같은 날짜의 추가 생성은 409로 거절하고 기존 일기는 수정할 수 있습니다. 사용자 행 잠금 안에서 중복 여부를 확인하므로 동시 저장도 한 건만 성공합니다. 기존 중복 기록과 적립 내역은 삭제하거나 변경하지 않습니다. 연속 기록 보너스는 아래 기준으로 추가 지급합니다.

| 연속 기록 | 추가 클로버 |
| --- | --- |
| 3일 | +1 |
| 5일 | +2 |
| 7일 | +3 |

연속 일수는 기록 날짜가 하루씩 이어질 때 올라갑니다. 같은 날짜의 중복 저장은 차단하며, 각 보너스는 해당 달성 날짜에 한 번만 지급합니다. 날짜가 끊기면 1일부터 새로 시작하며 7일 이후에는 추가 주기 보너스를 지급하지 않습니다. 이전 날짜의 일기를 추가해도 진행 중인 기록을 뒤로 돌리거나 보너스를 다시 지급하지 않습니다.

아이의 저장 요청을 DB 잠금으로 직렬 처리하고, 적립 원장의 사용자·보너스 사유·달성 날짜 조합으로 중복을 방지합니다. 정책 변경 전 지급한 보너스와 기존 잔액은 수정하지 않습니다.

## 일기 사진

일기 작성·수정 화면에서 사진 한 장을 첨부·교체·삭제할 수 있습니다. 브라우저에서 20MB 이하 사진을 줄인 뒤, 서버가 JPEG로 다시 변환해 PostgreSQL의 `diary_photos.image_data`에 저장합니다. 사진은 일기 상세의 인증·공개 범위 검사 후에만 반환하며 목록 API에는 사진 원본을 포함하지 않습니다. 사진 필드를 보내지 않는 이전 수정 요청은 기존 사진을 유지하고, 삭제는 `removePhoto: true`로 명시합니다. V19 마이그레이션은 일기 삭제 시 사진도 함께 지워지는 별도 테이블만 추가하므로 기존 일기를 변경하지 않습니다.

## 공통 상점 관리

어른 상점의 상단 메뉴는 **상점 / 상품 관리 / 받은 요청** 탭으로 이동합니다. 상점의 **아이의 선물 신청**은 아이가 가족에게 클로버 설정을 부탁한 개인 선물, **가족이 제안한 선물**은 가족이 특정 아이에게 직접 등록한 개인 선물입니다. 공통 상점 상품과 구분하며, 클로버를 사용한 선물 교환은 **받은 요청**에서 처리합니다.

선물은 아이가 가족을 지정해 부탁하고, 가족이 클로버를 정하면 개인 선물 목록에 표시됩니다. 교환 요청 시 클로버를 차감하고 거절 시 요청 당시 수량을 한 번만 돌려줍니다. 같은 아이의 동시 요청과 같은 요청의 승인·거절은 DB 잠금으로 직렬 처리합니다. 교환 대기 중인 목표는 ‘선물 요청 중’으로 표시하고 승인 시 해당 선물 목표만 완료하며, 거절하거나 다른 목표로 바꾼 경우에는 그 목표를 유지합니다.

가족이 선물을 전달한 뒤에는 요청한 아이가 **선물 → 요청 내역 → 수령 완료**를 누릅니다. 승인된 선물만 수령 처리할 수 있고, 아이·가족 내역에 수령 상태와 날짜가 표시됩니다. `PATCH /api/v1/shop/gift-requests/{requestId}/receipt`는 로그인한 아이 본인의 요청에만 적용되며, 중복 호출에도 최초 수령 날짜를 유지하고 클로버를 추가 차감하거나 환급하지 않습니다. V18 마이그레이션은 기존 요청을 변경하지 않고 수령 시각을 저장할 nullable 컬럼을 추가합니다. 수령 시각은 UTC로 저장하고 기기의 현지 시각으로 표시합니다.

아이·가족 구분(`app_role`)과 별도로 `users.user_role`에 `ADMIN` 또는 `USER`를 저장합니다. 가족 전용 운영에 맞춰 어른(`FAMILY`) 신규 가입은 자동으로 `ADMIN`, 아이는 `USER`가 됩니다. V20 마이그레이션은 기존 어른 계정도 `ADMIN`으로 변경하며 아이의 기존 권한은 건드리지 않습니다. 별도 관리자 지정은 필요 없습니다.

어른 화면의 **상점 관리 → 공통 상점 상품 관리** 또는 **마이페이지 → 공통 상점 상품 관리**에서 모든 아이에게 보일 상품을 등록할 수 있습니다. **상품 수정**에서 이름·설명·클로버·실제 구매가·쇼핑몰 링크·사진을 수정합니다. 사진을 바꾸지 않으면 기존 사진을 유지하고 교체·삭제를 별도로 지원합니다. 어른의 **상점 관리 → 공통 상점**과 관리 화면의 **상점 미리보기**에서 등록 결과를 확인하며, **상품 자세히**를 펼치면 전체 설명·구매가·쇼핑몰 링크를 볼 수 있습니다. 연결된 아이가 없어도 공통 상점을 확인할 수 있습니다. 삭제 상품은 새 요청·목표 선택·상점 목록에서 제외하지만 기존 요청 당시의 사진·가격·승인·환급·수령 기록은 유지합니다. 사진은 PostgreSQL에 저장됩니다.

`GET/POST /api/v1/admin/shop/products`, `PUT/PATCH/DELETE /api/v1/admin/shop/products/{productId}`는 기존 로그인 확인만 적용합니다. `PUT`은 상품 전체 정보를 수정하며, `imageData` 생략·null은 사진 유지, 새 데이터는 교체, `removeImage: true`는 사진 삭제입니다. 선택 사항인 구매가·링크는 null로 비울 수 있습니다. 기존 `PATCH` 클로버 수정도 유지합니다. 앞서 정한 범위대로 `ADMIN` 권한 검사와 관리자 전용 접근 차단은 아직 적용하지 않았습니다. 메뉴 표시는 권한에 따라 구분하지만 로그인한 일반 사용자도 직접 주소나 API로 접근할 수 있습니다. 프로필 수정·가입 요청에서 임의로 `user_role`을 지정할 수 없습니다.

갖고 싶은 선물은 공통 상점과 같은 2열 카드로 표시하며 **내가 신청한 선물 / 가족이 제안한 선물** 탭으로 나눕니다. 클로버가 정해진 본인의 상품만 각 탭에 표시하고, 설정 대기 중인 신청은 기존 요청 내역에서 확인합니다. 가족 제안 상품의 상세·교환 화면에서 목록으로 돌아오면 `?category=family` 탭을 유지합니다. 아이가 요청한 상품은 신청자와 지정한 가족, 어른이 직접 등록한 상품은 제안자를 표시합니다. V20 이전의 가족 등록 상품은 등록자를 저장하지 않았으므로 이름을 추정하지 않습니다. 이후 등록하는 상품부터 등록자 번호를 저장하고 현재 표시 이름을 조회합니다.


## 가족의 칭찬과 한 줄 영어

어른 홈과 아이 일기에서 아이 이름 탭을 선택하면 해당 아이가 공유한 일기만 표시됩니다. 홈에서 연 아이 일기 목록에도 선택한 아이가 유지됩니다. 상점 관리는 ‘아이가 올린 상품’과 ‘가족이 등록한 선물’을 탭으로 구분합니다.

어른 홈의 **함께하는 아이 → 아이 선택 → 클로버 주기**에서 1~1,000개의 정수와 칭찬 이유(최대 300자)를 입력합니다. 연결이 승인된 아이에게만 지급하며, 가족 이름과 이유가 아이의 적립 내역에 남습니다. `POST /api/v1/clovers/awards`는 `childUserId`, `amount`, `reason`, UUID `requestKey`를 받습니다. 가족·아이 잠금과 가족별 요청 키 유일 제약으로 같은 지급의 재전송을 한 번만 적립합니다. 같은 키로 다른 내용을 보내면 409를 반환합니다.

아이 홈의 **오늘의 한 줄 영어**는 PostgreSQL `english_contents`의 문장을 한국 시간 날짜에 따라 순환합니다. V22 마이그레이션이 기존 기초 문장 30개를 초기 데이터로 옮기며, 이후에는 관리자 화면에서 추가·수정합니다. 날짜별 선정 번호는 `english_daily_contents`에 저장하므로 문장을 추가해도 오늘의 선정은 유지됩니다. 아이는 읽고 뜻을 익힌 뒤 연결된 가족 한 명을 골라 확인을 요청합니다. 어른 홈 또는 **받은 요청**에서 지정된 가족만 ‘확인했어요 +1’ 또는 ‘다시 해보기’를 처리할 수 있습니다. 승인해야 클로버 1개를 적립하며, 다시 해보기에는 적립하지 않습니다. 거절된 요청은 같은 날 다시 보낼 수 있습니다.

영어 보너스는 **아이별 공부 날짜당 1개**입니다. 지난 날짜 요청을 나중에 확인해도 해당 공부 날짜의 보상으로 기록합니다. 날짜가 바뀐 화면에서 이전 문장의 확인 요청을 보내면 새 콘텐츠를 불러오도록 409를 반환합니다. 동시 승인과 재시도에는 최초 처리 결과를 유지합니다. 가족 연결이 끊어지면 요청을 확인하거나 지급할 수 없습니다. 새 기능의 아이·가족 관계 검증은 적용하며, 공통 상점의 관리자 권한 검사는 앞서 정한 범위를 유지합니다.

영어 API: `GET /api/v1/english/today`, `POST /api/v1/english/requests` (`receiverFamilyUserId`, `studyDate`, `contentId`, `contentVersion`), `GET /api/v1/english/requests` (로그인 가족에게 온 대기 요청), `PATCH /api/v1/english/requests/{requestId}` (`action`: `APPROVE`/`REJECT`). 날짜·문장·보상량은 서버가 결정합니다. V21은 요청 상태·문장·공부 날짜를 `english_studies`에 저장하고 기존 적립 원장에 지급 사유·가족 이름·재전송 키를 추가합니다. 기존 적립 내역은 유지합니다.

## 영어 콘텐츠 관리

**마이페이지 → 영어 콘텐츠 관리** 또는 **공통 상점 상품 관리 → 영어 콘텐츠**에서 영어 문장과 한국어 뜻을 추가·수정합니다. 각각 최대 120자이며, 검색·페이지 이동·오늘의 문장 미리보기를 지원합니다. DB에 저장되므로 콘텐츠 변경에 코드 수정이나 재배포는 필요하지 않습니다.

`GET/POST /api/v1/admin/english/contents`, `PATCH /api/v1/admin/english/contents/{contentId}`는 공통 상점과 같은 기존 로그인 확인을 적용합니다. 관리자 권한 검사는 이전 요청대로 보류한 상태이며, 관리자 계정 메뉴에서 진입합니다. 수정 시 현재 `version`을 함께 보내며, 다른 곳에서 이미 수정한 버전이면 409를 반환해 덮어쓰지 않습니다.

오늘의 선정은 최초 조회 시 DB 잠금으로 한 번만 정합니다. 오늘 문장을 수정하면 아직 확인 요청을 하지 않은 아이에게 최신 내용이 표시됩니다. 아이가 읽던 내용의 번호·버전과 요청 시점의 내용이 달라졌다면 409로 새로고침을 안내합니다. 이미 요청했거나 승인받은 공부는 `english_studies`의 당시 문장·뜻을 표시하며, 재학습 요청에도 이 내용을 유지합니다. V22는 기존 확인 요청과 지급 기록을 변경하지 않습니다.

## 로컬 실행

Node.js 22 이상, Java 21, PostgreSQL이 필요합니다.

백엔드는 기본적으로 `localhost:5432/wishdiary` 데이터베이스를 사용합니다. 기본 사용자·비밀번호는 로컬 개발용 `postgres`이며, 환경에 맞게 `WISHDIARY_DB_URL`, `WISHDIARY_DB_USERNAME`, `WISHDIARY_DB_PASSWORD`로 지정할 수 있습니다. 외부 배포 시에는 `WISHDIARY_AUTH_TOKEN_SECRET`도 별도로 설정합니다.

선물 사진은 기기에서 선택하면 긴 변 1,000px 이하로 줄여 전송합니다. 서버에서 실제 이미지인지 확인하고 메타데이터를 제거한 JPEG를 `shop_products.image_data` (`BYTEA`)에 저장합니다. 글과 사진은 함께 저장되며, 등록을 취소하면 업로드되지 않습니다. 모은 클로버로 선물을 요청할 때는 당시 사진도 `gift_request_notifications.product_image_data`에 보관합니다. 사진은 권한이 있는 선물 조회 응답에 포함되고, 별도의 공개 파일 주소는 만들지 않습니다. 사진을 포함한 백업은 PostgreSQL 전체 백업으로 할 수 있습니다.

```sh
cd backend
./gradlew bootRun
```

다른 터미널에서 프론트엔드를 실행합니다.

```sh
cd frontend
npm ci
npm run dev
```

화면은 `http://localhost:5187`, API는 `http://localhost:8080`에서 실행됩니다. 로컬 화면의 API 요청은 개발 서버를 통해 전달됩니다. 필요한 경우 `frontend/.env.example`을 참고해 로컬 환경 파일을 작성합니다.

cd backend

```

백엔드 테스트는 별도 H2 데이터베이스를 사용합니다.

```

Android APK와 iPhone 프로젝트 준비 방법은 [모바일 실행 안내](frontend/MOBILE.md)를 참고하세요. iPhone 앱 컴파일과 서명에는 Xcode가 필요합니다.

## 일기 화면과 그룹 탭

아이 일기는 **내 일기 / 그룹 일기** 메뉴로 구분합니다. 내 일기의 달력은 기본으로 펼쳐지며 날짜별 기록과 이전·다음 날짜 이동을 제공합니다. 그룹 관리는 마이페이지에서 진입합니다.

**그룹 관리**는 그룹명 탭으로 선택한 그룹의 구성원·수정·삭제 작업을 표시합니다. 기본 **우리 가족** 그룹은 구성원마다 이름과 아이/가족 구분이 있는 개별 카드를 표시하고 그룹 수정·삭제는 목록 상단에서 처리합니다. 그룹을 저장하면 해당 그룹 탭을 선택하며, 삭제 후에는 남은 첫 그룹을 표시합니다. **마이페이지 → 클로버 적립 내역**은 최신순 세로 목록이며 적립·사용·환급·보너스와 가족 이름·이유를 모두 표시합니다.

일기 작성·수정의 공개 범위는 기본으로 접고 현재 선택을 한 줄로 표시합니다. 누르면 **나만 보기 / 가족 보기 / 전체 공개 / 그룹 선택**을 2열 선택 UI로 펼칩니다. 그룹 목록과 새로고침은 그룹 선택일 때만 표시하며 여러 그룹을 선택할 수 있습니다. 새 일기의 기본 선택은 나만 보기입니다. 다른 공개 범위로 바꾸면 선택한 그룹을 해제하며, 그룹 공개에서 선택한 그룹이 없으면 저장할 수 없습니다. 접어도 선택은 유지되고 그룹 공개는 선택한 그룹 수를 표시합니다.

그룹 일기는 **전체 그룹 / 내가 만들었거나 참여한 그룹 / 전체 공개** 탭을 제공하며 탭에는 그룹명만 표시합니다. `GET /api/v1/diaries/shared-feed/groups`는 현재 볼 수 있는 그룹의 번호·이름·작성자 이름만 반환합니다. 피드의 `groupId`는 생략하면 기존 전체 피드, `-1`은 그룹 공개, `0`은 전체 공개, 양수는 해당 그룹입니다. 그룹별 필터와 접근 검증은 페이지 조회 전에 서버에서 적용하며, 다른 그룹을 통해 같은 일기를 볼 수 있더라도 참여하지 않은 그룹을 지정해 조회할 수는 없습니다.
